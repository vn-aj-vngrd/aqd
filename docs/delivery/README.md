# Delivery

Establish capability/resume work → current status. Validate a claim/update evidence → verification. Select/change an implementation slice → relevant plan section. Perform authorized branch/commit/PR operations → workflow. Merge/release → lifecycle delivery stages. Historical restoration/provenance → archive; routine tasks do not load chronology. Documentation completion is separate from required implementation acceptance.

| Document | Owns |
| --- | --- |
| [Per-issue execution plans](../pan/README.md) | Persisted vertical slices, commits, checks and resume actions, keyed by real issue number. |
| [Implementation plan](implementation-plan.md) | Dependency order, milestone exits and the first slice after authorization. |
| [Implementation status](implementation-status.md) | Current reproducible behavior and gaps. |
| [Acceptance proof](../agents/acceptance-proof.md) | UI AC E2E, rendered evidence and PR publication gates. |
| [Verification](verification.md) | Observed checks, limits and remaining release evidence. |
| [Workflow](workflow.md) | Local tooling, branches, commits, CI and release mechanics. |
| [Historical archive](archive/README.md) | Earlier prototype behavior, configuration and design-review logs. |

Follow [the agent lifecycle](../agents/lifecycle.md) for the ordered delivery procedure and authorization gates. [V1 release](../product/v1-release.md) owns launch acceptance; completing a milestone alone does not satisfy the full release.
