V2 adds a persistent Inbox root-toolbar entry (not a tab) and connected controls without replacing these private journeys; V1 has no Inbox.

## Welcome, onboarding and tour contract
L172 shows the same quiet native launch surface as V2 E01: centered AQD wordmark on the semantic canvas, without buttons, fabricated loading or an imposed delay. After launch, fresh install opens L60; returning users restore their valid local destination/draft. Welcome shares V2's wordmark, editorial photos, type and controls. Start my closet opens L61; Take a quick tour opens L62. Onboarding explains photo capture and manual classification, private local storage and export/device-loss limits before the first piece. Explore first opens empty Home. Permissions are requested only when the user chooses the corresponding media action. Local profile name and avatar stay optional. L61 Personalize my closet opens six questions L152–L154/L166–L168 plus review L169 before L04. Every entered step has an unnumbered header title and separate Step n of 7 progress and requires an explicit answer or No preference/refusal; no Skip question/Skip setup controls remain. Height/body shape are not compulsory measurements and body use starts off. Explore first remains an entry outside this questionnaire without marking preferences completed. Settings → Style and Profile → More → Style reopen the identical saved-answer flow. Profile has one More icon for Add fit/Edit profile/Style/Wear insights/Settings. No account or clothing quota is required.

L61 action hierarchy: Personalize my closet is the prominent blue action; Take the tour is a centered plain blue text action below it, with regular weight, no background, border, blur or shadow and a 50-point minimum target. Adjacent primary/secondary actions use a 12-point gap in a dedicated group, matching light/dark Welcome and L66. Explore first is a centered plain text action at the bottom, above the home indicator, with no background, border or shadow and a 50-point reference hit area. Native layout respects the bottom safe area; short screens, larger text and localization place the footer after scrollable content when needed so actions never overlap.

Tour steps show Home, Closet, Agent and Profile with explicit **Preview only** labels. Demonstration content never becomes a real record. Each step has Back, Next/Finish and Skip; Back on the first step returns to its entry. Finishing from Welcome opens L66 with Add my first piece / Open Home. Open Home uses the same plain text secondary treatment and 50-point minimum target. Skipping opens empty Home, or returns to Settings when replayed. Settings → Take the tour replays it without changing wardrobe, drafts, preferences or last real destination. Store completion/skip and step state locally; returning users do not repeatedly see onboarding.

For accessibility, focus moves into the tour sheet, background controls are inert, progress and actions have meaningful labels, and larger text uses scrollable content rather than clipped copy. The tour stays readable in dark mode, Reduce Motion/Transparency and localization. Existing users who update to V2 do not repeat the V1 tour; explain only newly enabled connected controls after opt-in.

L66 uses an illustrative knit/trousers/loafers composition and a noninteractive Add a piece → Make a look → Plan a day roadmap. “Ready when you are” avoids implying a saved wardrobe. The copy explicitly says tour examples are not saved; Add my first piece and Open Home retain the shared 12-point action spacing. Artwork and roadmap do not create records or represent completed progress. Native accessibility hides decorative garment images and reads the roadmap as one short explanatory phrase.

## Local interaction and recovery
L04 starts with no photo and empty required fields. Its approved empty state uses one compact full-width Add photo row, not an empty portrait well or separate camera action. Add photo opens L159's native source sheet: Choose from Photos presents the system PhotosPicker; Take photo presents native camera. Close, outside tap or swipe returns to the unchanged draft and restores focus to Add photo. Once media is accepted, the photo viewport is portrait 3:4 and preserves the whole source with Fit by default. L75 shows an accepted portrait photo; L76 demonstrates a landscape photo without clipping. Edit photo opens L77 with optional crop, rotate, reset and zoom; Use photo returns to the draft, while Cancel keeps the previous selection. Change opens L78's native options. Removing media preserves metadata. Missing media with completed fields reaches L79's retained draft and disabled Save; adding a photo returns to L75/L76. Only a valid photo/name/category save reaches L05. The second row of section 02 shows these media states alongside independent returning Home L23. [Photo capture and editing](capture-photo.md) owns exact geometry, original retention, import/failure/cancellation and native API boundaries. Save remains the sole primary form action.

Every entry has native Back and preserves the original draft. A dirty exit offers Keep editing / Discard changes. Save follows validation and successful local persistence; failed/unknown execution reconciles one operation identity. PhotosPicker/camera refusal or cancellation retains manual entry. Search has loading/empty/no-match/error states and restores the previous query/scope.

All complete private W/O/P/A contracts apply within the phase boundary. Shared forms/menus/pickers/sheets cover selected dates, recurrence, activity/destination/timezone, availability, rename/membership, archive/restore/delete, reporting range and actual wear correction. L36 is the routine example; its event/trip variant collects destination/activities instead of recurrence, then uses L40/L42 and L38/L39. Existing private canonical references remain reusable and are mapped in [coverage](v1-coverage.md).

Use on-device Foundation Models for supported bounded drafting; validate eligibility/readiness and selected context. Keep Agent visible; show L19 for ineligible hardware, L80 when Intelligence is off and L81 when the model is preparing. Direct manual routes remain available. Image or speech intake appears only when a demonstrated on-device path is available; unavailable features explain the limitation without a cloud fallback. External research, human messaging and live weather are V2 extensions.

## Returning Home insight

L23 retains one compact Closet in use card beneath the weekly wear summary. The September fixture shows 8 of 12 active pieces worn (67%) and opens L41 for that same period. The whole card is a single accessible navigation target; the progress bar is redundant to its numeric label. Use recorded wear only, with the same denominator and reporting rules as Insights. This is descriptive utilization, not a completion goal. Show the most recent completed reporting month with recorded data; if there is no such month, omit the card rather than inventing a percentage. Empty first-piece Home remains simple. At smaller sizes or larger text, scroll the dashboard with bottom safe-area padding so the card and navigation never overlap.
