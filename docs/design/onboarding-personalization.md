# Shared onboarding and editable preferences

October 6, 2026. Owner-approved Paper/spec refinement only. V1/V2 use the same private preference questions during onboarding and from Settings → Style or Profile → More → Style. This supersedes the earlier three-step-only restriction. [V1 flow](v1-flow.md) owns placement; [Profile](../features/profile-account.md) owns local privacy/durability and [Agent](../features/agent.md) owns capability/context limits.

## Seven numbered steps: six questions and review

| Reference | Question / inputs | Purpose |
| --- | --- | --- |
| L152 | What would you like help with? Wear more of my closet / Plan outfits faster / Try new combinations; choose up to two. | Rank useful actions and eligible owned-piece combinations, not fabricated progress. |
| L153 | What do you dress for? Everyday / Work / Evenings / Active days / Travel; multiple choices. | Suggest occasions without inferring employment, a schedule, calendar events or weather. |
| L154 | What feels like you? Explicit style choices, including relaxed, minimal, classic and bolder directions; multiple choices. | Soft style ranking; no identity, gender or body inference. |
| L166 | How do you like clothes to fit? Fitted / Regular / Relaxed / Oversized; optional comfort, fabric, coverage or avoidance preferences. | Use declared comfort/fit preferences rather than equating a body type with a preferred silhouette. |
| L167 | Optional height with explicit cm or ft/in units; optional self-described body shape via native picker, with Not added / Not sure / Prefer not to say. Use body details for suggestions is off in fresh setup. | Optional proportion context only after purpose-specific opt-in. No photos, weight, age, health, gender or inferred measurements. |
| L168 | Which colors and patterns do you prefer or avoid? Explicit choices; unknown is valid. | Rank known garment metadata; do not infer coloring, ethnicity, undertone or ownership. |
| L169 | Review preferences; Edit each answer group; Save preferences. | Review exactly what will be saved and whether optional body details may be used. Unanswered fields say Not answered; explicit No preference/refusal is a recorded response, not a guessed default. |

Fresh setup starts unselected, with body-use consent off. Once the questionnaire is entered, every question needs an explicit response: a substantive answer or an honest No preference / Not sure / Prefer not to say. None is mutually exclusive with substantive choices. Continue is disabled until that step is valid; an empty field must not silently become a default answer. Body measurements remain optional: explicit refusal completes that step without sharing height/shape or enabling their use. Color/pattern fields may remain blank only with explicit No color/pattern preference.

Use unnumbered navigation titles: Your goals; Your occasions; Your style; Fit & comfort; Body details; Colors & patterns; Review preferences. Do not prefix header titles with 1.–7.; numbering belongs only in the separate progress label. Beneath the header show a quiet step n of 7 label and semantic-accent progress track. Review is 7 of 7, not a persistence receipt. Remove Skip question and Skip setup from every question, review, Settings-mode and V2 copy. Back remains available; cancellation discards only the draft with native dirty-exit protection, never marks setup completed.

L170 shows the shared first question with an illustrative saved goal in Settings mode; L171 shows the body-shape native picker over the same fifth step, with an unnumbered Body details header. L173 shows Describe in my own words: a private multiline custom-shape draft, explicit Use description and Cancel, with the same shared V1/V2 return contract. L169/UP07 illustrate an incomplete restored-review state with Save disabled; the valid mode displays exact answered/declined values and enables Save only after validation. Progress means current step, never saved/completed data.

V2 equivalents are UP01–UP07; E05 enters them, W20 and U05 Settings reopen the same sequence in edit mode. V1 Style remains L45 → the shared questions, and Settings L13 exposes Style. L61 Personalize my closet enters this sequence before first-piece capture. Explore first still opens Home without a questionnaire. Returning users are not repeatedly prompted. Settings and Profile Style open the same questions with saved answers and the true return destination; they do not force capture or repeat Welcome. V2 does not require account creation or add cloud consent to the private questionnaire.

## Draft, save and privacy

- Back preserves the draft. Explicit clear/remove updates it; unanswered is distinct from an explicit No preference or refusal. A refusal must not silently erase unrelated saved answers in Settings.
- There is no questionnaire skip action. Changed-draft cancellation uses native Keep editing / Discard protection; Settings cancellation preserves the prior saved preferences and returns to its actual source. The existing Explore first entry remains outside this entered questionnaire and creates no completed-preferences flag.
- Review shows explicit answers/refusals, height units and body-use state. Save requires every step answered or explicitly declined and commits the complete preference draft atomically. Onboarding success continues to L04; Settings/Profile success returns to the preserved source. Failure retains all input and offers retry with the same operation identity; no success or recommendation refresh until persistence confirms.
- Height is an optional user-entered positive finite value. Normalize storage to centimeters without changing the user's preferred display units; round-trip cm/ft/in without silently altering a saved measurement. Missing or removed height/body shape remains unknown. Unusual values need honest validation rather than normative body judgments.
- Describe in my own words opens L173 from the L171 picker. Use description requires a nonblank custom draft of at most 160 grapheme clusters, with a live count; reject an over-limit value without silent truncation. The illustrative draft is My shoulders are broader than my hips, not a measured/inferred body attribute. Cancel restores the prior picker choice; Use description returns with a pending custom selection, and Done applies it only to the preference draft. Atomic review Save remains the persistence boundary. Editing a description never enables body-use consent. Native keyboard, growing field/scrolling and focus return require device verification.
- Body shape is a self-description, not a diagnosis or an objective measurement. No ideal/normal category, body score, flaw language, auto-tagging or automatic photo-derived shape is allowed. Not sure and Prefer not to say are valid. Users can clear these details or revoke their use at any time.
- Save answers locally in V1 with the existing profile/preferences protection, explicit export/validated restore and erase boundary. These fields are private, not public-profile attributes or telemetry. V2 does not publish them, silently migrate them into prompts, or treat local consent as permission for cloud transmission.
- Optional body details enter recommendation/Agent context only when their purpose-specific use is enabled **and**, for Agent, Style context is enabled. Turning either permission off excludes them from new attempts; changing settings never mutates an already-running request. V2 cloud inclusion needs separate explicit provider/data-scope consent; exclude body details by default. Answers are context, not model training.

## Recommendations with and without Apple Intelligence

Deterministic eligibility comes first: owned, active, available pieces; valid composition; the requested date/occasion; explicitly pinned items and known constraints. Preferences rank eligible choices, never invent garments, bypass availability or record wear. Unknown attributes contribute no assumed match. Explicit avoidances must be checked against known metadata; unknown fabric/fit is labelled unverified rather than promised suitable.

Use a simple baseline before model assistance: rank declared occasion/style/color matches, respect explicit exclusions, and explain one factual reason. Goals prioritize a useful Home action, not a fabricated score, streak, confidence percentage or claim of learning. Unknown history is not proof that a piece was never worn. When no eligible suggestion exists, offer Add piece, Build outfit or the relevant honest empty state.

Supported on-device Foundation Models may draft bounded outfits/plans with the same allowed preferences and wardrobe IDs. Validate proposed IDs/compositions and require review before saving. Height/self-described shape may guide an opted-in discussion of proportions; neither supplies garment measurements or proves an exact size, physical fit, health claim or try-on result. The user can override any suggestion. Unsupported hardware/model/language, failure or cancellation retains deterministic/manual paths and reason-specific L19/L80/L81; no automatic cloud fallback.

The existing Apple [Foundation Models availability](https://developer.apple.com/documentation/FoundationModels/generating-content-and-performing-tasks-with-foundation-models) and [onboarding guidance](https://developer.apple.com/design/human-interface-guidelines/onboarding) remain references, not proof of AQD runtime capability.

## Acceptance and evaluation

- PREF-01: No Skip question/Skip setup controls exist. Complete all numbered steps with answers or explicit No preference/refusal, without an account, body measurement or AI-capable device. Blank substantive steps disable Continue; review cannot save an incomplete draft. Cancellation preserves records; manual paths remain available.
- PREF-02: Open the identical flow from onboarding, Settings and Profile; save/cancel returns to the correct source, with prior answers and drafts preserved. V2 uses the same private questions.
- PREF-03: Save/restart/export/restore/erase answers, unit choices and body-use state; failed/interrupted saves preserve the prior record and retry creates one update.
- PREF-04: Clear optional height/shape and switch body use off; new deterministic/model requests exclude those details. Style context off excludes them even when body use is on. No photo inference, public exposure, telemetry or implicit cloud inclusion.
- PREF-05: Test unknown/all-explicitly-declined answers, mixed style/occasion goals, explicit avoidances, unavailable pieces, no eligible outfits, missing fit/fabric metadata and cm/ft-in round trips. No body category causes an exclusion or exact-size guarantee.
- PREF-06: Compare deterministic baseline and supported model drafts on the same representative closets. Require valid owned/available IDs and pinned-item retention, zero disallowed context leakage and factual reason text; report preference relevance, override rate and constraint failures separately. Measure device latency/cost before widening assistance; no benchmark, speed or improvement is claimed by the designs.
- PREF-07: Verify consistent unnumbered header titles and separate step n of 7 progress across both entry modes/phases; largest Dynamic Type, VoiceOver question/choice/progress order, toggle state, RTL/localized units, keyboard/scroll/safe-area footer, focus return, light/dark semantic roles and Reduce Motion/Transparency on actual supported devices.

Paper establishes only the rendered question, review and return contracts. It implements no persistence, recommendation ranking, model integration or native interaction. Light screens are the current visual inventory; Foundations retains dark partners for every light color role.
