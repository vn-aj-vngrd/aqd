# Design handoff by phase

Read [rules](rules.md) and [DESIGN.md](../../DESIGN.md). [iOS Paper](https://app.paper.design/file/01M3SM2KBHBZG6MA0Q744Y9NW0) and [web Paper](https://app.paper.design/file/01M3W6P0PN9SSQ1J3N6V23A9WK) own visual UI. The iOS file has exactly three pages, in order: **00 · Foundations**, **01 · V1**, **02 · V2**. Foundations is the reusable design-system library: tokens, typography/spacing/shape, a labelled icon catalog, native navigation primitives, controls, surfaces and generic component states. App screens, feature menus/journeys, feeds and full-phone accessibility examples live in the owning V1/V2 reference area, preserving their IDs rather than becoming new routes. The current library has19 reusable boards and seven category headers (26 roots), including [app-owned semantic feedback](components.md#app-owned-semantic-feedback); five native API/ownership boards plus **Transparency · Native iOS** extend the historical12-board/six-header library without new phone journeys. The [native catalog](native-ios.md#transparency--native-ios-foundations-reference) maps26 product-relevant role families (25 original rows plus feedback Label), deployment18 and guarded26/27 enhancements; [portable evidence](evidence/native-ios-transparency.json) records provenance and exact27-kit inspection limits. The manifest records current board ownership. Foundation groups organize a library, not a user funnel. [Library evidence](evidence/foundations-library.json) records moved references and the41-role/12-alias icon catalog. Structural clones require explicit synchronization. V1 has nine ordered journey groups, with supporting states beside their owning flow; dark phone duplicates are removed while Foundations retains paired light/dark colors. V2 has nine groups covering canonical features, connected journeys and future expansions; shared private UI matches V1, with public/account/sync/Inbox additions instead of a replacement Profile layout.
