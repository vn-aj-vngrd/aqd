## Entry, suggestions and focus

A34 is the default new-conversation entry with native keyboard focus. A01 is the same welcome after the keyboard is dismissed. Focus the multiline editor once after the full-screen presentation finishes; never repeatedly refocus on stream chunks, picker dismissal, error, history restoration or background return. An entry from a focused assistance action retains its prompt and selected records. Opening an existing conversation restores its draft and reading position without raising the keyboard automatically. VoiceOver navigation and an attached hardware keyboard take precedence over automatic focus.

Center the empty-state welcome heading and supporting introduction; center compact suggestion-chip groups below them. Keep message, response and editor text leading-aligned. Keep one quiet welcome and compact useful suggestions near the composer: Tonight’s look, Plan my week, Rediscover unworn pieces and Start with a piece. Starter prompts use opaque surface/night-surface capsules, 32-point base visible height, 14-point horizontal padding, 14/20 regular action-text labels and 8-point gaps, with separate nonoverlapping native hit bounds of at least 44 points, without blur, outlines, shadows, disclosure chevrons or AI badges. Center related chips in one or two rows; allow wrapping/growing controls at larger text sizes rather than shrinking labels. These are prompt actions, not selected filters. Suggestions fill an editable draft; they never send automatically. Start with a piece opens A36. Hide the welcome suggestions after a message is sent; completed replies may offer relevant short follow-ups that also fill the draft. Missing wardrobe/context uses A55 with general styling and Add piece, without claiming ownership. Long suggestions scroll horizontally or reflow at accessibility sizes; touch targets stay at least 44 pt.

Agent navigation uses the shared centered detail-title style: 20/26 pt, medium weight and shared title tracking, matching review/task screens. The header More menu contains New conversation, Conversations and Manage context. New conversation preserves the previous conversation and draft; destructive conversation deletion uses the existing explicit confirmation. Back restores the originating destination. The Agent remains separate from human Inbox.

## One native glass composer

Use one regular Liquid Glass functional shell containing a transparent native TextEditor, optional attachment rail and a compact toolbar. The toolbar contains Attach (+), a context selector, Dictate (microphone), and Send / Stop in one stable 44 pt position. Neutral controls live within the shared shell; do not stack glass on every child. Send is prominent only when valid input and supported runtime are ready. Empty Send has the native disabled trait; do not rely on a pale color alone.

Text starts at body size, grows through roughly one to five visible lines, then scrolls internally. Use a keyboard-safe inset rather than hard-coded keyboard heights. Return inserts a newline; sending is explicit. Retain native selection, paste, dictation, editing menus, spelling and hardware-keyboard support. A nonempty supported attachment may initiate a message without text; unsupported or preparing attachments require resolution first. Limits come from runtime/media configuration and display an actual remaining count or specific validation error. Reaching a limit retains the entire draft for editing; never silently truncate it.

Persist the draft and selected references before opening a picker or moving to history. Restoring a draft reconciles attachment access/readiness rather than promising stale files remain readable. During generation, the editor accepts a separate next-message draft; Stop remains in the send position and the next draft is never sent or erased implicitly. A48 keeps Stop until cancellation is acknowledged, suppressing duplicate taps; A14 then labels the retained partial response incomplete.

A37 illustrates an attachment rail with removable selected-piece and photo pills. Expand a pill to inspect its exact context; removal has a separately labelled 44 pt target. Pinning a piece is an explicit requirement for the proposed outfit, not an accidental consequence of attachment. Keep the other selections and text when removing one attachment.

## Photos, camera and files

Attach opens the native menu/reference A35: Choose photos, Take photo, Browse files and Select closet pieces. Photos uses the system selected-media picker without full-library access; Camera uses the native capture/permission flow; Files accepts supported images through the system document picker. Cancel returns to the unchanged draft. On compact phones, selection/review uses native sheets or navigation within the task; iPad adapts to an anchored popover when appropriate.

A38 reviews the selected image. Attach photo includes it only in this message. Add as a closet piece opens the existing item review/save flow and requires an actual persistence receipt. Neither path silently publishes, saves an item or requests unrelated images. Normalize/validate each image off the main thread; show A39 while preparing. Keep an individual state for selected, preparing, ready, failed and removed. Failure A40 names the real cause: unreadable image, unsupported format, exceeded size/count or lost access. Offer Retry only for retryable failures; unsupported/oversized content offers Replace or Remove. Other ready attachments survive one failure. Do not claim a network upload when processing is local.

An attachment does not prove image understanding. A54 explicitly explains unsupported image assistance and offers Describe photo, Add manually or Remove. The default model context still excludes unselected photos, private notes and Inbox. Only explicitly attached images may enter a validated supported image path; do not silently switch to a cloud provider. Capability, privacy and real-device quality gates must close before image analysis is enabled.

## Closet selection and context

A36 searches the private closet with Pieces / Outfits / Themes. Selection is read-only context; Use selected adds typed owned IDs/revisions to the draft. Outfit/theme selection resolves its allowed members, deduplicates piece IDs and names unavailable members. Preserve selections across categories, search and cancelled review. A47 covers no matches; an empty closet offers Add piece or General styling. Shared X01–X04 loading/read-failure/offline/cache states apply to each category; show cached records when safe, and Retry without discarding selections. Deleted, archived, inaccessible or changed records are revalidated before sending and again before proposal approval.

A46 selects My closet (bounded relevant authorized records), Selected pieces (only chosen records), or Without closet (general styling; no wardrobe/history reads). A55 shows General in the composer. The context summary exposes actual included records, source limits and missing facts. Scope changes affect the next request and preserve text; they do not rewrite the context of a running attempt. Manage context opens A06. L28/A06 use one opaque 12-corner group for the three 64-point context toggles, without separators; Included scope is a separate 54-point surface. Style context includes only allowed saved preference answers; optional height/body shape additionally require their purpose-specific use permission. They remain excluded by default from cloud context and public data. Done commits once and returns to the retained task; Cancel/Back leaves the prior context unchanged. Weather uses explicit place/date through A33, with source/time and unavailable coverage. No default Inbox or private-note access.

## Voice input

Voice is dictation with review, not an always-listening or continuous spoken-response service. A41 explains access before the native microphone/speech prompt. Request permission only after an explicit microphone tap; never on autofocus. Start recording only with permission and supported on-device recognition. Cloud transcription is not authorized by this design. A42 shows Listening, actual elapsed recording time and a waveform from measured audio level; sample values on Paper are illustrative. Finish recording starts A43; Discard stops capture and returns to the retained text draft without sending.

A43 identifies transcription separately from recording and Agent generation. A44 uses a native editable text area; Use transcript merges at the captured insertion point in the draft and never sends. Preserve concurrent text edits; confirm replacement when required rather than overwrite. Record again leaves the typed draft intact. Voice audio is transient and cleared after accepting/discarding its transcript; do not attach it to chat history or telemetry by default. Clearly explain a retryable retained recording before keeping it beyond the current capture step.

A45 distinguishes microphone denied (Open Settings / Keep typing), speech unavailable (Keep typing), no speech detected (Record again / Keep typing) and transcription failure (Retry transcription when audio remains available / Record again / Keep typing). Camera denial has its own A53. Interrupted capture stops the microphone; backgrounding or an audio interruption never implies continued recording. Restore any received transcript and explain the interrupted state. Offline voice works only if on-device recognition is actually available; connectivity alone does not disable local text assistance.

## Stream and recovery

Use the existing response lifecycle A08/A11–A18/A22–A30 with the richer composer. Waiting/preparing shows one native spinner and a subtly shimmering status label. The shimmer is a narrow user-requested exception to the default no-loop motion policy: only the busy label, no moving prose, no token animation and no shimmer across the whole screen. The page-00 master shows a static tonal phase. Native standard mode uses a restrained luminance sweep around 1.8 s per cycle; use the existing readable secondary/primary tones, not transparent unreadable text. Reduce Motion, VoiceOver and backgrounding use a static label with the same semantic status. Stop the shimmer immediately at terminal status. It is decoration, never progress or hidden reasoning.

Stream received Markdown in readable chunks, preserve completed block identity and show actual event-backed phases. After first text, render that text immediately rather than hiding it behind a skeleton. Keep actions disabled on unfinished proposals until structure/IDs validate. Auto-follow only while already at the latest content; A50 offers Jump to latest without pulling a reader away. Preserve exact partial source on Stop, interruption and timeout. A49 represents a terminal timeout; Try again creates a fresh response from the reviewed original request, while Edit message changes the next request. Retry never reuses approval or repeats a committed action.

Send failure A29, generation failure A15/A49, attachment failure A40 and unknown write outcome A09 are separate states. Use one stable client message ID for a send retry and reconcile write operation IDs before any write retry. Complete responses offer Copy, Retry when supported and More/details. Server-collected ratings and response-version comparison remain V2. Approval/review A03/A10/A31/A32 and receipts A04 are trusted structured content; generated words such as “saved” are never proof of execution.

## Appearance and acceptance

A51 uses opaque neutral shells and controls, no blur or translucent edges. A52 demonstrates larger text and the expanded editor; wrap context labels and reflow attachment/actions without shrinking type. Dark D02 uses the same controls, state meaning and V2 action set. Validate RTL, VoiceOver focus/labels, 44 pt remove/Send/Stop targets, keyboard gestures and Increase Contrast on the native app. Static Paper is insufficient to certify Liquid Glass optics, animation, recognition, streaming or persistence.

Implementation acceptance: new-chat autofocus once; returning-chat focus retained; multiline/long input; picker cancel/denial; one failed attachment among ready ones; all three closet categories and stale/deleted selection; no-context insights; denied microphone; no speech; speech/permission unavailable; transcription error/cancel/interruption; editable transcript with concurrent typing; first-token error; fragmented Markdown; midstream interruption; slow/hard timeout; Stop acknowledgement; scrolled-up reader; background restoration; send retry deduplication; stale approval and unknown save outcome. Every path preserves the applicable draft and offers the exact recovery action.
