# Today — personal in-app widget stack

Owner-approved October 7, 2026. V1 private local feature, inherited unchanged by V2. **Specification and Paper only; not implemented.** [Design](../design/today.md) owns composition and reference IDs. [V1 release](../product/v1-release.md) owns launch scope; existing wardrobe/outfit/planning/wear/journal contracts still own their records.

## Outcome and boundary

The first destination is **Today**, with the existing house icon and accessibility name Today. Customize Today opens a draft editor. Users add, configure, duplicate, remove and reorder AQD widgets and their own notes/photos. These are in-app cards, **not WidgetKit or system Home Screen widgets**. No external Calendar, Reminders, web, music, integration or new AI source is approved. Existing optional WeatherKit remains its separately consented exception, not enabled by adding a widget.

Commit at least **one** instance. No arbitrary maximum or duplicate-kind limit. Stable instance IDs distinguish repeated kinds and independent personal content. First-use stock order: `todayLook`, `weekInWear`, `closetInUse`; empty data changes card content, not the saved instance list. Existing saved configuration is authoritative: never silently add unavailable/missing kinds or reset a personalized layout. The same stock configuration applies to empty, planned and optional-weather demonstrations. Illustrative photos/text are never inserted as user records.

## Durable configuration and ownership

`TodayConfiguration` is a local presentation preference: local owner, schema version, revision and ordered instances. Each instance has stable instanceID, known kindID, configuration, personal-content revision and AQD-owned media references. Summaries query existing records rather than duplicating wardrobe/plans/wear/journal. Personal notes/photos are explicit writable local data. No backend, WidgetKit timeline, analytics store or AI orchestration is required.

Use valid persisted configuration first, then validated last-known-good data. Only an absent first-use store gets stock defaults. Corrupt/newer schema preserves original bytes and blocks overwrite pending explicit recovery. An ephemeral Quick actions fallback may keep navigation usable without claiming repair. Recover dirty drafts separately from the committed layout; unknown operations reconcile before retry/resume. Minimum one applies to instances, not currently available source records.

Include configuration, personal content, accepted originals, recipes and recoverable drafts in the existing versioned reviewed local archive; automatic backup/upload remains off. Restore stages/validates schema, ownership, media, references, unique IDs and minimum one before atomic replacement. Failure/cancel retains the good store. Erase affects AQD-owned data only, not original Photos or exported copies. This feature does not change body-use consent or implicit wear/publication/AI boundaries.

## Editing, commit and return states

| State | Transition / invariant |
| --- | --- |
| View → clean draft | Customize copies the committed revision; no persistence yet. Clean Back writes nothing. |
| Add / configure | Library selection opens nested draft. Apply validates into parent draft only; Cancel retains the previous parent selection. Nested dirty exit protects only nested edits. Theme/photo/nonempty-note prerequisites are real validation, not invented counters. |
| Dirty draft / remove | Edit/add/remove updates draft identities only. Attempting to remove the last instance does not mutate and keeps focus: “Keep at least one widget. Add another before removing this one.” |
| Reorder | Drag/onMove and Move up/Move down operate on the same IDs. First/last boundary actions disabled; announce position. Done in reorder returns the ordered parent draft, not a store receipt. |
| Dirty exit | Source-anchored native routine decision: Keep editing/no-write dismissal preserves draft; Discard changes drops only layout and unsaved personal edits. Existing records are unaffected. No discard while write outcome is pending/unknown. |
| Restore defaults / Undo | Review stock three and retained personal content. Restore is provisional layout change; Undo restores exact prior draft before Done. Removing/restoring layout placement does not erase saved personal content; type configuration can explicitly choose a retained local personal card, copying an independent instance snapshot. No implicit original-Photos selection or shared mutable text follows. One-level acknowledged layout Undo retains referenced assets until released; no wardrobe/plans/wear/journal deletion. |
| Done / saving | Revalidate ≥1, known schema/kind, unique IDs, ownership/revision, valid required content and prepared media. Required content/prepared-media checks apply to new or replaced Note/Photo content. An unchanged saved instance with unavailable backing media stays explicitly unavailable and does not force silent removal/reset or block unrelated valid layout edits. One stable operationID, one logical atomic configuration/content/media-reference commit. Disable mutation/duplicate Done during pending write; preserve readable draft. |
| Confirmed success | Only write acknowledgment updates visible committed layout and offers layout Undo/receipt. Restore trigger focus and source scroll. No success for pending, failed or unknown results. |
| Confirmed failure | Keep prior layout and full draft. Retry same intent only after confirming noncommit; Keep editing returns to draft. |
| Unknown / reconciling | Read committed operation/revision before retry. Acknowledged commit succeeds once; proven noncommit becomes confirmed failure; unresolved remains unknown. Cancel after commit is not rollback. |
| Background/restart | Recover staged draft independently; resume pending operation through reconciliation first. Preserve editor selection/focus where possible; do not replace saved configuration with demo/defaults. |

## Retained personal cards — review and delete

Customize → Add widget → Note/Photo configuration exposes **Saved notes and photos**, a local retained-content list (not the system Photos library). Include title/preview, content kind and truthful usage state; selecting a card copies an independent instance snapshot. The list remains reachable when no personal card is currently on Today, including after Restore defaults. No hidden orphan collection or automatic retention purge is allowed.

Each retained card has a native More → **Delete saved note/photo** action. Review names the exact card and AQD-owned data affected, explains that removal from Today alone does not delete it, and uses a critical native alert with explicit **Cancel** / **Delete**. Original Photos, wardrobe/journal records, independent copied cards and exported copies are unaffected. Cancel/dismiss writes nothing and returns focus/scroll to the selected row.

Revalidate owner/content revision and every media reference immediately before committing. Active instances and recoverable/dirty drafts block deletion, with actionable links to remove the active placement and finish or explicitly discard its edits first; pending/unknown writes must reconcile before any delete. A retained layout Undo reference is disclosed in the delete review: confirming Delete also releases that specific Undo, never silently other drafts or saved cards. Delete atomically records one stable operationID, removes the eligible personal-content record and its reference edges, and invalidates the disclosed Undo. Only acknowledgment removes the row/offers success; no deleted content remains in future exports. Physical originals/derivatives are removed only after acknowledgment and a complete reference check across other cards/records/drafts/Undo. Shared assets stay; failed cleanup is queued safely for retry and never falsely reported as completed erasure.

Confirmed failure retains the card/media/selection and offers Retry or Cancel. Unknown completion retains readable state, reconciles operation/revision before retry, and cannot replay or resurrect deleted content. Restart resumes reconciliation/cleanup; error is not an empty list. Empty retained content says no saved notes/photos. After confirmed deletion, focus moves to the next row or empty-state heading; Back returns to the unchanged parent layout draft. No automatic upload, AI use, wear or publication results.

## Media lifecycle

Prepare replacement before replacing the accepted draft reference. Bind import result to owner/instance/draft revision/selection token; ignore late, superseded or cancelled results. Cancellation/permission denial/camera unavailability/invalid media/iCloud download failure preserves fields and previous photo. Accepted photos become metadata-minimized AQD-owned local originals separate from derivatives/recipe; original Photos are never changed/deleted. Cleanup only unreferenced staging after work stops; release replaced originals only after acknowledged commit and reference checks across cards, records, Undo and recoverable drafts. Missing/corrupt saved media remains an honest unavailable instance, never another garment fallback.
