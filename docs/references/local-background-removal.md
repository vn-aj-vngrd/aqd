# AQD: optional local photo background removal

Research scope: Apple primary sources only; documentation review, not device testing. Findings support the [capture design contract](../design/capture-photo.md), not a working implementation. Recommendations below are product policy, not guarantees of Vision's output.

## Evidence (five primary sources)

1. [VNGenerateForegroundInstanceMaskRequest](https://developer.apple.com/documentation/vision/vngenerateforegroundinstancemaskrequest) — Apple describes a request generating an instance mask of noticeable objects separated from background. Apple's [documentation JSON](https://developer.apple.com/tutorials/data/documentation/vision/vngenerateforegroundinstancemaskrequest.json) records **iOS/iPadOS 17.0** minimum (Mac Catalyst 17.0, macOS 14.0). This is the older Objective-C-compatible Vision API.
2. [GenerateForegroundInstanceMaskRequest](https://developer.apple.com/documentation/vision/generateforegroundinstancemaskrequest) — the Swift struct generates `InstanceMaskObservation`; `perform` is async/throwing. Apple's [documentation JSON](https://developer.apple.com/tutorials/data/documentation/vision/generateforegroundinstancemaskrequest.json) records **iOS/iPadOS 18.0** minimum (Mac Catalyst 18.0, macOS 15.0). Merely removing `VN` does not preserve the iOS 17 deployment boundary.
3. [WWDC23: Lift subjects from images in your app](https://developer.apple.com/videos/play/wwdc2023/10176/) — authoritative explanation of subject/mask semantics and execution. Apple says Vision image analysis happens **in-process**, is hardware-optimized but resource-intensive, and should run off the UI thread. Subject lifting is **“class agnostic”**; foreground objects can be segmented regardless of semantic class. Subjects need not be individual objects: Apple's example combines a man and his dog into one subject.
4. [VNRequest.cancel()](https://developer.apple.com/documentation/vision/vnrequest/cancel()) — documented as **“Cancels the request before it can finish executing.”** [Documentation JSON](https://developer.apple.com/tutorials/data/documentation/vision/vnrequest/cancel().json) confirms this wording. It does not promise instantaneous UI cancellation or roll back a result already committed by the app.
5. [WWDC24: Discover Swift enhancements in the Vision framework](https://developer.apple.com/videos/play/wwdc2024/10163/) — new APIs adopt async/await and return observations directly; old APIs remain available. Requests can be memory-intensive; bound concurrency. Some requests remove CPU/GPU support on Neural Engine devices; supported compute devices can be queried. This is compute selection, not an Apple Intelligence readiness check.

### Local processing and readiness

These are **Vision image-segmentation APIs**, not Foundation Models language-model APIs. The cited Vision execution model is in-process, with Apple's hardware optimization [3,5]. A local-only AQD pipeline need not upload the photo or call Apple Intelligence/Foundation Models. No Apple Intelligence enrollment, language-model download, or Apple Intelligence-capable-device gate is documented as a prerequisite in these request references [1,2]. Do not label this feature “Apple Intelligence” or gate it using Foundation Models availability.

OS availability is not proof of acceptable latency, memory use, or segmentation quality on every supported phone. Choose one API matching the app deployment target, handle actual execution errors, and validate physical devices; do not promise that all iOS 17 devices produce equally good results. The cited references do not establish a complete per-model performance/readiness matrix.

### Masks and what they do not establish

Apple's WWDC23 explanation [3]: background pixels have label **0**; foreground labels start at **1**, are contiguous, but have no guaranteed ordering. When subjects are found, the old request's results contain a single observation, not one observation per garment. `allInstances` excludes background; selecting a subset of indices chooses detected instances. A soft segmentation mask can be generated at source resolution; the masked image can preserve the input extent or be tightly cropped. Index labels are not clothing categories; soft alpha values are not garment-correctness confidence.

**Documented fact:** class-agnostic subjects can combine objects [3]. **Product inference requiring evaluation:** a worn shirt may be retained with its wearer rather than isolated; an outfit or overlapping garments may form one subject; a hanger, mannequin, or nearby object may be retained or removed. Multiple labels mean multiple detected subjects, not necessarily multiple garments; a single label does not prove a single clothing piece.

Low contrast, sheer/translucent fabric, lace, straps/fringe, occlusion, shadows, reflective details, and hangers are proposed stress cases, **not documented categorical failure guarantees**. Do not promise automatic garment isolation or edge repair. These sources expose no guaranteed garment-specific correctness/partial-edge detector. Do not invent a confidence threshold/API. Generic observation confidence, if present in the chosen SDK, is not established here as a calibrated garment/edge-quality signal. Structural checks (no subject, empty output, image-render failure) can catch unusable results, but do not reliably prove semantic correctness. Partial removal/incorrect edges remain device-evaluation and user-judgment concerns.

## Smallest safe flow (proposed policy)

1. Capture/import one piece into the existing draft. Original is the default; manual save remains available without removal.
2. Explicit **Remove background** action; helper copy: “Works best with one item against a clear background.” No automatic processing on every capture.
3. Show “Removing background on this device…” and **Cancel**. Keep expensive work off the UI path [3]. Limit to one active photo job.
4. Success opens **Original / Cleaned** comparison and **Use photo** for the selected rendition. **Cancel** preserves the previously accepted draft photo; deliberately selecting Original and using it restores the source. Show transparency against a neutral backing; allow inspection of fine edges. A successful request is not automatic approval.
5. Apply only to the current draft, only after confirmation; keep original data and a reversible choice. Do not overwrite a saved piece or silently finalize/save the draft.
6. Unavailable: “Background removal isn't available. You can keep the original.” Failure/no subject: “Couldn't remove the background. Keep the original or try another photo.” Offer retry/retake without blocking save.
7. Multiple detected instances are potentially ambiguous, not proven multiple garments or a processing failure. AQD's bounded policy previews the union of detected foreground instances: a legitimate pair of shoes can have two labels. Require user review, not a new instance-selection editor or an automatic reject based on count. Retained people/hangers/clutter and poor edges can be rejected with Original or Cancel, then manual crop/retry/another photo. A single instance also requires review; no claim the app always detects bad edges.

### Cancellation/race contract (app responsibility)

For the VN path, request cancellation uses `VNRequest.cancel()` [4]. A Swift Task around an old synchronous request is not by itself evidence that Vision computation is cancelled. New Swift APIs are async [2,5], but the reviewed sources do not establish a foreground-request-specific immediate Task-cancellation guarantee. Do not overclaim it.

Independently of stopping computation, Cancel must immediately abandon the UI job and preserve original/draft state. Associate each job with a draft ID, source-photo revision and job token; invalidate on cancel, retake, retry, dismissal or save. Check identity and cancellation before publishing a preview and again before applying. Discard stale completions and cancellation-related errors instead of surfacing failure or changing the draft. A request completing concurrently with Cancel must never resurrect the preview or overwrite a replacement photo.

## Proposed acceptance and evaluation (not yet verified)

**Static/prototype review:** every action has a destination/return state; processing has Cancel; comparison labels and apply/keep actions are unambiguous; unavailable/failure/ambiguous states preserve manual save; cleanup never claims clothing recognition; original retention/draft-only apply are explicit. Check VoiceOver labels, Dynamic Type, non-color state cues and accessible targets. Static review cannot validate actual masks, hardware support or races.

**Native tests:** physical oldest-supported phone and modern phone, iOS 17 VN boundary if supported and iOS 18+ chosen path. Offline/airplane-mode processing; confirm no photo upload in the app pipeline. Test supported/unsupported OS routing, injected execution/render failures, no subjects, rapid repeated actions, cancel immediately/before completion/after completion, retake or save while running, navigate away and re-enter. Assert no stale preview, no draft corruption, original remains recoverable, and manual save works in every fallback state. Record latency, peak memory and UI responsiveness rather than inventing guaranteed timing.

**Representative corpus:** approximately 30–50 consented garment photos, including easy flat-lay controls; light-on-light/dark-on-dark; patterned clutter; hanging garments/hangers; mannequins; worn pieces/full outfits; adjacent and overlapping garments; sheer/lace/fringe/thin straps; shadows/reflections; rotated and high-resolution imports. Log device/OS/API revision, detected-instance count, processing failures and user acceptance. Human reviewers score target-garment retention, unwanted person/hanger/background retention, edge clipping/halos and preservation of transparent details, at thumbnail and enlarged views. Use masks/ground-truth comparisons where practical, but aggregate overlap alone misses thin-detail damage. Report subgroup failures and false acceptance; agree a product acceptance threshold from results before making quality claims. No corpus/device evaluation was performed in this research.
