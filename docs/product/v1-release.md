# AQD V1 release definition

Updated October 5, 2026 with the owner's clarification: **V1 is a complete usable private app on one Apple device, not a thin closet demo.** It has Home, Closet, Planner, Agent, a local Profile, complete Settings/onboarding and light/dark appearance. It delivers the private wardrobe/outfit/planning journey end to end without an app backend. V2 extends that same app and data with connected features and future enhancements. This branch remains documentation/design only.

The October 1 connected V1 is preserved in [V2 core release](v2-release.md); its private requirements are retained here where device-only operation applies. [V2 backlog](v2-backlog.md) preserves everything else. No feature is discarded by the phase split.

## Release promise

On an iPhone, start privately, add owned pieces, create useful outfits/themes, prepare dates/routines/trips and packing, ask Agent for supported wardrobe help, record actual wear and inspect history/insights. Reopen all local records after restart; manage local Profile/preferences and Settings; export/restore/erase your data. These are complete journeys with loading, empty, error, permission, cancellation and success paths.

No account, social participation, network connection or AI-capable hardware blocks manual wardrobe/planning. V1 Agent is a real local destination with history, review, cancel/retry/copy and truthful capability states. Eligible, ready devices use on-device Foundation Models; other devices show reason-specific Agent unavailability, and manual controls remain available. Do not promise every generative question on every device.

iPhone remains the first Apple-device target; additional iPad/Mac/Watch/Android/web clients are future extensions. Commit **iOS 18.0 as minimum deployment for the complete manual core**, building with published stable **Xcode 27 / iOS 27 SDK** (latest stable maintenance checked at implementation). [Primary research](../references/native-ios-materials.md) justifies the selected16–18 APIs and supported deployment range; this is a specification, not a reproduced build. Native components render each OS automatically; custom26 glass and optional27 styles are guarded with baseline/opaque fallback. Foundation Models requires26 plus compatible device/runtime readiness and does not raise the manual minimum. Physical-device capability and optional weather entitlement/network are separate release checks. Free local use is the working default; no subscription/entitlement backend in V1.

## Optional live weather contract

Owner-approved V1 scope, inherited by V2: direct native Apple WeatherKit, not an AQD backend, end-user account or cloud LLM. Core records remain private/local and usable offline; V1 is **not strictly zero-network**. WeatherKit's iOS 16+ API does not lower AQD's existing manual iOS 18 planning target. Developer Program membership, App ID service/capability and signed entitlement are required; no end-user Apple/AQD login is required for this feature.

Weather starts off. Before city search or weather-request actions, disclose that manual city text uses online Apple Maps/search/geocoding and selected coordinates plus date/range go to Apple WeatherKit. Neither receives closet records, photos, body details or chat. Manual city selection needs no device-location permission. Only an explicit **Use current location** gesture may request When In Use and one-shot foreground location; approximate is acceptable, never Always/background tracking. Denial/offline/timeout retains manual city/core paths. Cancel never enables weather or applies context; Apply changes only the parent draft's context, not saved outfit/plan records.

Show only returned current temperature/condition and selected-day low/high/precipitation when available. Forecast coverage is at most ten days, bounded by actual returned periods, not every day of a two-week plan or three-calendar-month routine. Missing/out-of-range/historical dates show unavailable, never inferred weather or current-as-future substitution. Keep source, selected place/timezone/date, provider timestamps and local fetched-at distinct; resolve or disclose unknown timezone. No invented weather becomes a logged fact. Public snapshots never refresh automatically.

Confirmed **AQD budgets, not Apple quotas**: coalesce one in-flight request per location + dataset/date-range key across visible consumers. Request only needed datasets, foreground-visible only; automatic refresh only when missing/expired and no more often than every 30 minutes. Manual Refresh has a 60-second cooldown, one in-flight request and no retry loop. Freshness ends at earliest required provider expiry or 30 minutes after fetch. Retain at most five local location snapshots with at most ten returned daily entries each. Expired same-place/date data may show **Saved weather — updated [time]** for at most 24 hours after fetch; never use it as fresh Agent input. After 24 hours hide numbers. Off purges the cache. Unit changes format canonical measurements locally without refetching.

Display the SDK-supplied light/dark Apple Weather mark and SDK legal attribution link beside fresh **and** saved values; cache supplied assets, never invent logo text/assets. If attribution is unavailable, withhold numerical weather and offer recovery. [Weather context](../design/weather-context.md) owns interaction states; [Apple evidence](../references/weatherkit-v1.md) separates facts from AQD policy. Advanced providers/context, research, calendar, alerts/notifications and expanded travel/collaboration remain V2.

## Data contract

Persist a versioned local database and protected media in the app sandbox. A local closet/profile identifier is not an online account. SwiftData with CloudKit explicitly disabled is a proposal; preserve a suitable recovered existing store rather than rewrite it merely for an API preference. Use stable item/outfit/theme/plan/history/conversation IDs and safe migrations.

Prepare required media before committing references; preserve old images until replacement saves. Archive preserves links; deletion previews outfit/theme/future-plan effects and retains minimal non-photo historical facts. Conversation/profile/preferences and journal memories/notes/date-timezones/outfit snapshots/media/drafts are local data, subject to export/restore/erase controls. Journal outfit deletion retains minimal composition facts without unexpectedly erasing memories; available media is reference-scoped and unavailable media labelled honestly. Journal replacement/deletion cleans only unreferenced AQD-owned media after commit, not outfits/wear records, other memories or original Photos assets. Private notes and images do not enter Agent context unless a separately supported explicit local selection allows it.

AQD-owned stores/photos/drafts/derived data are excluded from automatic device backups by default. Export creates a versioned archive locally and invokes the native document interface only after an explicit action. Explain its sensitive contents and that the destination can be cloud-backed. Restore is a reviewed full replacement with staging/validation and recoverable original data until completion. Device file protection does not establish encryption for an exported archive at its chosen destination.

## Apple-native assistance and complete experience

Use native navigation/tab controls, forms/menus/sheets, PhotosPicker/camera/document pickers, semantic system text and OS appearance/accessibility. Foundation Models supports bounded text/structured drafting using confirmed local metadata, not guaranteed image understanding or current information. Check hardware/OS/enablement/readiness/language/region at runtime; preparing the model can require network before later offline use.

Agent stays visible on every supported iPhone. Eligible/ready devices get local conversation and reviewed proposals; unavailable devices get a reason-specific explanation and direct routes into manual creation/planning. Long plans may use bounded reviewed batches; manual routines/trips are complete regardless of generative quality. Local contextual input can state occasion/preferences, user-entered conditions or explicitly selected fresh WeatherKit context under the contract above; the model itself has no live-weather knowledge. Speech/image intake requires a verified on-device implementation before enabling, with typed/metadata fallback and clear unavailable states. Do not add model adapters, a generic orchestration platform or external API beyond the approved optional WeatherKit/Apple city-lookup exception just to call V1 complete.

## V2 extends V1

V2 adds online identity/account lifecycle, opt-in association/sync/backup/recovery, social profiles/curated closets, All/Following/discovery, publishing/follows/comments/bookmarks, human Inbox/moderation/admin, remote push, advanced external weather providers/context, calendar/research and the complete future enhancement roadmap. It retains V1's Home/Closet/Planner/Agent/Profile/Settings, private journeys, records and design foundations. Inbox is a persistent V2-only 44-point root-toolbar entry into I01, not a tab; no Inbox appears in V1; local Profile gains connected/public controls only after opt-in. No V1 data reset or mandatory redesign is part of this transition.

Advanced capture, try-on/shopping, inferred/automatic-learning personalization beyond the explicit shared questionnaire, purchases/cost-per-wear, richer community/chat, subscriptions, additional platforms and measured infrastructure growth remain in [V2](v2-backlog.md), with requirements prepared. Device-local feasibility alone does not approve every future enhancement for the MVP; existing private core journeys are complete and new features can be added after real usage.

## Known limitations and completion

One installation is authoritative. Device loss/app deletion/corruption without a retained export can lose the closet; automatic second-device recovery is not promised. No app backend or recurring backend bill is required, but Apple distribution/support/device costs and potential paid WeatherKit capacity remain separate. WeatherKit includes 500,000 calls/month per Developer Program membership, shared across users, not a per-device allowance; aggregate usage/capacity needs validation. On-device resources/model quality are finite; unsupported generative capabilities never block manual work.

After separate implementation authorization, establish the source baseline and complete every private slice and LOCAL check with build/commit/device evidence. Review actual native appearance/navigation/accessibility and offline recovery. Paper is a prepared UI requirement, never runtime proof. [V1 flow](../design/v1-flow.md), [coverage](../design/v1-coverage.md), [status](../delivery/implementation-status.md) and [verification](../delivery/verification.md) own the handoff.

Agent availability follows the [reason-specific contract](../features/agent.md#agent-availability-and-provider-selection): L19 unsupported, L80 disabled, L81 preparing. LOCAL-12 includes tab visibility and draft/history preservation without a misleading composer. V2 retains an explicit provider option, with no V1 cloud fallback.
